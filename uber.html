A green lane for low-risk changes

1234 Approval loop5

Automated Check & Commit-Bound Stamp

  • Example: Replacing a deprecated logging call on commit a3f9c21.
  • Required Signals: No high-risk AI review findings, passing CI (build, lint, tests), clean security scan, low risk/blast radius, team path policy match, and re-verification right before approval.
  • Bot Stamp: Automated approval applies strictly to that exact commit SHA.

Green Lane vs. Human Review

  • Risk-Gated Landing (Early Adopters): Low-risk PRs with all checks green receive an automated stamp and enter the merge queue.
  • Human Review Path: High-risk changes, unresolved findings, or human-only paths continue to require person-in-the-loop review.

What We Learned

  • Teams prefer configurable risk thresholds so high-risk items are flagged while routine changes flow smoothly.
  • Engineers and agents expect fast verdicts measured in minutes.

What AI review looks like on a PR

123 Review loop45

PR Diff & Severity-First Comments

  • Scoped to Changed Lines: Focuses on modified code (such as pricing/quote.go) with direct links back to the agent run trace.
  • High Severity Example: Warns against overwriting an existing promo value with an empty result on lookup failure.
  • Medium Severity Example: Flags using floating-point arithmetic for monetary totals where rounding drift can occur; recommends a dedicated money type.

Review Detail & Repo-Defined Team Skills

  • Run Summary: Completed review surfacing 3 findings in ~2m 40s with log access and source attribution (general review, AI linter, or team skill).
  • Team Skills (SKILL.md): Teams encode domain rules directly in their repository (such as avoiding floats for currency and logging price adjustments).
  • What We Learned: Over-arguing arbitrary confidence scores erodes trust when a high-confidence comment is wrong; transparent traces and comments support systematic tuning.

Main that repairs itself

12345 Merge loop

Traffic Shaping & Verified Main

  • Peak Traffic Rules: Very large PRs wait until peak load subsides so fast changes keep moving.
  • Self-Repairing Sequence: PRs pass quick checks to land on main, while batched full checks run asynchronously; failures trigger auto-fix or revert.
  • Deployment Gate: verified main advances as intermediate commits pass full checks, and production deploys only from verified main.

Lessons & Reference Links

  • Queues designed for human cadence bottleneck under agent throughput.
  • Shape peak traffic before overhauling queue mechanics, and build reusable fixers across loops.
  • Talk & Repo: Full talk video on YouTube (youtu.be/hX140a5klW0) and open-source submit queue at github.com/uber/submitqueue.
